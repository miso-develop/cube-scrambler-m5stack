# Research

Resolve factual uncertainty before turning it into a design assumption.

State the concrete question, inspect relevant repository code/config first, then prefer primary sources such as official documentation, specifications, source code, release notes, first-party APIs, or vendor documentation.

Check dates and versions when behavior may change. Distinguish sourced fact from inference and follow contradictory evidence until explained or explicitly unresolved.

Return finding, evidence/source, implication for the current work, and remaining uncertainty. Do not change implementation merely because research found a possible improvement unless it is in scope or explicitly requested.
